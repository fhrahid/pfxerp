# Current role-guard evidence matrix and target decisions

**Evidence status: IMPLEMENTED source paths, UNVERIFIED deployed behavior.** This is an effective *source-level* route/service matrix, not an approved future grant list. The six primary roles are `H` CHRO, `P` CPO, `T` CTO, `F` CFO, `M` PM and `D` Developer. `E` is CEO and documented separately. Current CHRO has no system-role or guard mapping (`src/modules/roles/roles.service.ts:9–20`; `prisma/schema.prisma:14–21`). Each cell names only roles with an evidenced route and passing role check; omitted roles are **UNVERIFIED for future policy**, not automatically permitted. `All` means any authenticated role, including custom. `—` means no corresponding handler was found in the scoped controllers; it does not prove a business prohibition. `*` means a service-level condition in the cited source still applies. CEO appears in cells where the global override reaches the handler, unless a service rechecks role. Source: `src/common/guards/roles.guard.ts:15–33`.

Operations: **Create** starts a record; **Read** retrieves it; **Update** changes content/state without a dedicated approval; **Delete** removes/revokes; **Assign** maps people/squads/work; **Approve** accepts/verifies/finalizes; **Submit** offers work/request for review; **Export** produces a download or extract; **Manage** covers policy, settings, treasury or lifecycle administration. A POST can therefore be `Submit`, `Approve`, or `Manage` rather than `Create`.

Scope codes: `o` own; `s` active assigned squad; `g` organization-wide query or cross-squad action; `r` restricted role/state; `?` scope or authority unresolved. `g` reports what the current query exposes, not a recommended target entitlement. A cell such as `M:s,E:g` is conditional per actor. Every resource row cites its enforcement path; controller plus service must be read together for state conditions.
