# Repository audit handoff

**Phase 1 status:** complete as a source audit on 2026-11-07, followed by owner decisions and read-only local database schema inspection. The repository contains runnable code and specifications. No application code or configuration was changed, and no tests or application API calls were run. The audit inspected 208 handwritten source, configuration and documentation files in batches; the file-by-file checklist and exclusions are in [coverage-checklist.md](coverage-checklist.md).

## Confirmed architecture

The API is a NestJS 11 application with a default `/api/v1` prefix, global validation/JWT/role/throttling pipeline, Swagger, Socket.IO events, scheduled work and a Prisma/PostgreSQL data layer (`src/main.ts:11–59`, `src/app.module.ts:40–90`, `prisma/schema.prisma:1–10`). A static browser console is served from `public/` by the API, while a separate Next.js 14/React console lives in `frontend/` (`src/main.ts:25–26`, `frontend/package.json:5–40`). The root Compose file provisions PostgreSQL and API; the Next frontend has its own Dockerfile (`docker-compose.yml:1–52`, `frontend/Dockerfile:4–34`).

The schema declares 43 models and 30 enums (`prisma/schema.prisma:14–1083`). Read-only inspection of the owner's chosen local PostgreSQL baseline found 43 application tables, 415 public columns, 30 matching enums and both migrations finished; see [database-baseline.md](database-baseline.md). Financial movements use account/ledger transaction/ledger entry records and a serialized HMAC chain (`src/modules/ledger/ledger.service.ts:46–183`). Backend controllers and services are registered across 24 business modules (`src/app.module.ts:54–77`). The route inventory contains 143 declared HTTP routes, including one handler with two paths, plus a Socket.IO gateway (`docs/srs/audit/evidence-map.md`, `src/events/events.gateway.ts:18–56`).

## Uncertainties to carry forward

**Later policy update:** DEC-03 now specifies ABAC with an explicit CEO-managed per-person service/action grant as one required subject entitlement. Earlier audit wording that treated ABAC and direct grants as alternatives is superseded. See `docs/srs/DECISIONS.md` DEC-03 and `docs/srs/access/service-access-policy.md`.

The code calls the combined people role `CPO` (`prisma/schema.prisma:14–21`); the target separates CHRO and CPO, allows multiple roles and moves to ABAC (`docs/srs/DECISIONS.md`). Custom roles can be stored but have no general permission policy (`src/modules/roles/roles.service.ts:70–102`, `src/common/guards/roles.guard.ts:15–33`). WebSocket rooms lack authentication/ownership checks (`src/events/events.gateway.ts:25–39`). Browser notice envelopes omit a separate `tag`, but dispatch does not require it; the selected future envelope does (`frontend/lib/notice-crypto.ts:74–89`, `public/app.js:2547–2562`, `src/modules/notices/notices.controller.ts:55–70`). The Next client exists despite the README deferral (`frontend/app/page.tsx:13`, `README.md:162`). Redis/BullMQ, TimescaleDB, CASL and R2 are future requirements, absent from current runtime manifests (`plan/main.md:38–58`, `package.json:22–54`, `docker-compose.yml:1–52`). The payout loop is per squad, so README’s all-batch atomic wording is unsupported (`README.md:81`, `src/modules/sprint-payouts/sprint-payouts.service.ts:108–190`). The second migration is untracked, though the local database records it as finished (`prisma/migrations/20261107000000_align_schema/migration.sql:1–120`, `docs/srs/audit/database-baseline.md`).
